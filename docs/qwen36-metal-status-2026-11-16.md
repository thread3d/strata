### Root Cause Analysis

**K-quants (Q4_K/Q5_K/Q6_K/Q3_K) dequantization mismatch:**

The `ref_quant.cpp` dequantization matches llama.cpp's `dequantize_row_q4_K`. The Metal kernel's `Dec<F>::run` and `unit_combine` implement the same formula mathematically.

However, `expert_parity` with synthetic weights (generated by `ref::random_blocks`) shows:
- gu kernel: h rel L2 1.11 (GPU vs CPU reference)
- down kernel: y rel L2 4.7e6

The `random_blocks` function only sets block scale/min (bytes 0-3), leaving group scales/mins (bytes 4-15) and codes (bytes 16+) as random bytes. Both CPU and GPU should produce identical results for identical random data, but they don't.

**Possible causes:**
1. Metal `X<F>::load` for gu kernel reads xprep buffer differently than CPU expects
2. Floating point precision: CPU uses double, GPU uses float (but 1.11 rel L2 is too large)
3. `unit_combine` formula implementation difference
4. `scale_min_k4` packing/unpacking mismatch

**Real model symptom:** gu outputs (h) ~2000-6000 (should be ~0.1), down outputs (ye) ~10^10. Suggests weight scales ~1000x too large.
